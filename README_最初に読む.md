# SHEET MASTER v2.9(完成版一式)

このフォルダは、そのままビルドしてアップロードできる Xcode プロジェクト一式です。
**ソースコードの変更・既存コードとの合体はしないでください。**(前回、旧画面と混ざって読み取り結果が表示されませんでした)

## 作業は3つだけ
1. 今のリポジトリの中身(アプリのプロジェクトとソース)を、このフォルダの中身に**丸ごと置き換える**。
   GitHub Actions などのアップロード用の設定ファイルは今のものを残してよい。
   その場合、ワークフロー内のプロジェクト名・スキーム名を `SheetMaster.xcodeproj` / `SheetMaster` に合わせる。
2. `Config.xcconfig` の3行(Bundle ID・Team ID・ビルド番号)だけを書き換える。
   Bundle ID は今の TestFlight のアプリと同じにする(同じアプリの更新になる)。
3. Release でアーカイブして TestFlight にアップロードする。

## 中身
- iOS 17 以上 / SwiftUI / 外部ライブラリなし
- バージョン 2.6、アイコン・カメラ/写真の許可文・暗号化申告(なし)は設定済み
- 共有スキーム `SheetMaster` 入り(コマンドラインからもビルド可)
  例: `xcodebuild -project SheetMaster.xcodeproj -scheme SheetMaster -configuration Release -destination 'generic/platform=iOS' archive -archivePath build/SheetMaster.xcarchive`

## もしビルドエラーが出たら
エラーの出た行の文法・型だけを直し、画面構成・読み取り処理・データの形は変えないこと。

## v2.9 の変更点(形のずれの修正+「図面と見比べる」画面の追加)
対象の例: 日新電子工業 チェーン裏カバー 天板(長円の板、φ85・φ9・長穴、t2.3)。
- **円弧の端がある板の形がずれて表示される不具合を修正**(`Geometry/Geometry.swift`)
  - 原点合わせと展開寸法を「頂点だけ」で測っていたため、長円の板などは円弧が原点の外にはみ出し、縦の寸法も短く出ていた(例: 本来 約439 → 357.27 と表示)
  - 円弧のふくらみまで含めて測るように修正。**DXFの座標にも効く**(v2.8では円弧の部分がマイナス座標になっていた)
- **曲げの読み落としのチェック**
  - 部品一覧で曲げがあるのに、展開に曲げ線が1本も無いときは、理由を添えて自動で1回読み直す(`Reading/DrawingReader.swift`)
  - それでも無いときは「確かめてほしいこと」に表示する
- **「図面と見比べる」画面を追加**(`Views/PreviewViews.swift`)
  - 「② 形を確かめる」の各部品カードで、データのすぐ下に黄色の「図面と見比べる」ボタン(拡大画面の左上「見比べる」、DXF画面の拡大からも開ける)。押すと、左に図面の写真、右に出したデータを**同じ縮尺・同じ向き**で並べる
  - 穴ごとに同じ色・同じ番号の四角で囲む。写真とデータで四角の位置が合っていれば正しく読めている
  - 穴が3か所以上あるときは、写真の位置とデータの位置のずれを計算し、大きい穴に「⚠︎ ずれ約○mm」と表示
  - 「重ねる」に切り替えると、写真を半透明にしてデータを重ねて表示(濃さはスライダーで調整)
  - 拡大・移動は左右が連動する。一覧の穴をタップするとその四角が太くなる
  - そのために、AIに各穴の「写真の中の位置(ピクセル)」も答えさせるようにした(`Reading/Prompts.swift`、`Reading/ImagePreprocessor.swift`)
  - **v2.8以前に読み取った図面は写真の位置が無いので、「指示して読み直す」で読み直すと見比べられる**(読み直さなくても写真とデータは並べて表示される。縮尺はそろわない)
- バージョン表記を 2.9 に変更(プロジェクトファイルはバージョン番号の2か所だけ変更)
- **新しいファイルは追加していない**。`Config.xcconfig` の**ビルド番号だけ前回より大きく**してアップロードする

## v2.8 の変更点(「板の部品が見つかりませんでした」でデータが出ない不具合の修正)
対象の例: 日新電子工業 DM231906J-M088 モータカバー(SUS304 t1.5、1枚もの、M6溶接ナット付き)。
- **原因1:AIの返し方を読み落としていた**
  - AIが部品一覧などを「JSONの文字列」の形で返すことがあり、v2.7 まではそれを0件として扱っていた
  - `Reading/DrawingReader.swift` の `J`(読み取り結果の解析)を、文字列でも中身を解析して使うように修正
  - 部品一覧・外形・穴・曲げ・面データのすべてに効く
- **原因2:1枚ものの図面で、板を「対象外」にしてしまうことがあった**
  - 部品表が無く、溶接ナットや焼け取りの指示がある1枚ものの図面で起きていた
  - AIへの指示に「品名の板は必ずレーザー部品として入れる」「溶接ナットは購入品として別の行に、穴(φ7)は板に入れる」を追加(`Reading/Prompts.swift`)
- **自動の読み直し**
  - 板の部品が0件のときは、理由を添えて洗い出しを1回だけ自動でやり直す
  - それでも0件なら、表題欄の品名で板を1つ自動で追加して展開を読みに行く(「確認してください」欄に表示)
  - これで「データを出せない」状態では終わらない
- 一部の範囲だけに付くタブや、段の付いた側板がある部品の書き方を、AIへの指示に追加
- バージョン表記を 2.8 に変更
- **新しいファイルは追加していない**。`Config.xcconfig` の**ビルド番号だけ前回より大きく**してアップロードする

## v2.7 の変更点(2種類の板がある図面で、片方が読み込めない不具合の修正)
対象の例: 日新電子工業 DM131095J-M008(① チェーン裏カバー t2.3:長円の板の両側にフランジ/② チェーンカバー t1.2:長円の前板+側壁を溶接)。
- **長円・円弧の端・斜めカットのある板に曲げがある部品を読めるようにした**
  - v2.6 の「面モデル(faces)」は基準面が長方形の部品しか表せず、こうした部品は形を作れなかった
  - AIへの指示(`Reading/Prompts.swift`)に「基準面が長方形でない曲げ部品は外寸並べ(outer_dims)で書く」ルールと例を追加
  - 展開計算(`Geometry/Geometry.swift` の `unfold`)を修正。曲げ線の上にある点を、展開後の曲げ線の位置(控除の半分手前)に寄せるようにした。v2.6 では円弧の端とフランジの角が約2mm食い違い、外形が壊れていた
  - 曲げ線の範囲(start/end)を受け取り、フランジのある所だけに曲げ線を描くようにした
  - 円弧が曲げ線をまたいで半径が合わなくなったときは、「確かめてほしいこと」に出すようにした
- **溶接で作るカバーの分け方を追加**
  - 円弧に沿った側壁は、「前板」と「側板(帯板)」の2部品に分けて読むようにした
  - 帯板の展開長は「直線の合計+中立半径×角度」で出すようにした
  - 溶接・塗装の指示がある板を「対象外」に分けないようにした
- **自動の読み直し**(`Reading/DrawingReader.swift`)
  - 1回目の回答から外形が作れなかったときは、理由を添えてAIに1回だけ自動で読み直させる
  - 回答が長すぎて切れたときは、説明を短くさせて再送する
- **画面**(`Views/ResultView.swift`)
  - 形が作れなかったとき、その理由を赤字で表示するようにした
  - 「レーザー対象外」の欄に「板として読む」ボタンを追加。AIが板を対象外に分けてしまっても、ボタン1つで読み直せる
- バージョン表記を 2.7 に変更
- **新しいファイルは追加していない**(既存ファイルの中身だけ変更)。プロジェクトファイルはバージョン番号の2か所だけ変更
- `Config.xcconfig` は前回の Bundle ID・Team ID のまま、**ビルド番号だけ前回より大きく**する
- 以前に読み取った図面もそのまま開ける。読めなかった部品は「指示して読み直す」を押すと、新しいルールで読み直す

## v2.6 の変更点(読み取りの失敗対策)
- **通信をストリーミング(少しずつ受信)に変更**(`Reading/ClaudeClient.swift`)。
  v2.5 は回答が全部できるまで通信が無言になり、曲げのある図面では数分待った末に接続が切れて「読み取れない」になっていた。
  読み取り中は「受信 ○○字」が増えていくので、動いているかどうかが見える。
- **AIの「考える機能(thinking)」を使用**。使えないモデル・キーの場合は自動で外して再送する。
- **曲げ部品の展開方式を変更**(`Geometry/Geometry.swift` の `FaceBuilder`、`Models/Models.swift` の `FaceModel`)。
  AIには「基準面+フランジの外寸と穴の位置」だけを答えさせ、展開座標・曲げ控除・角の逃げ・U溝・角Rはアプリが計算する。
  v2.5 の「外寸を並べて控除を引く」方式は、箱形(4辺曲げ)だと角の寸法が左右でずれていた。
- 読み取り中は画面が消えないようにし、アプリを一瞬切り替えても通信を続ける。
- 「数値を直す」画面に、曲げ部品の面の寸法・穴・切欠きの入力欄を追加。
- **新しいファイルは追加していない**(既存ファイルの中身だけ変更)。プロジェクトファイルの変更は不要。
- `Config.xcconfig` は前回の Bundle ID・Team ID のまま、**ビルド番号だけ前回より大きく**する。
- 以前に読み取った図面は、そのまま開ける。曲げ部品は「指示して読み直す」を押すと新方式で読み直す。
